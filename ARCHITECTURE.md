# Архитектура MVP — «Умный поиск на сайте» (задача №3, команда №2)

Одна страница. Цель — работающий поиск без LLM на каждом запросе, с прозрачным ранжированием и аналитикой.

## Поток запроса

```
q ──► нормализация (ё→е, регистр, CamelCase, раскладка) ──► токены + стемминг (Snowball RU/EN)
  ──► исправление опечаток (RapidFuzz по словарю каталога+словарей, только для неизвестных слов)
  ──► словарь: фразы-синонимы/сленг/аббревиатуры → «концепты» с альтернативами
  ──► отрицания («без облака») → отрицательные ограничения
  ──► точный матч ID/названия ─┐
  ──► BM25 по полям (name, vendor, category, attributes, description) ─┴► кандидаты
  ──► coverage gate: доля IDF-веса концептов запроса, покрытая товаром (иначе → нулевая выдача)
  ──► relevance gate: только товары с rel ≥ 0.75·rel_top получают бизнес-буст
  ──► бизнес-буст (популярность, маржа, контекст: сегмент/история) в пределах ±0.1
  ──► top-K + объяснение (поля-источники, подтверждённые атрибуты, исправления, синонимы, latency)
  ──► журнал JSONL без ПДн ──► /analytics (нулевые выдачи, неудовлетворённый спрос, latency, воронка)
```

## Модули (`app/`)
| Файл | Назначение |
|---|---|
| `config.py` | все веса/пороги в одном месте, пути к данным (переопределяются env) |
| `data_loader.py` | импорт каталога/словарей/событий JSON/JSONL/CSV через `field_mapping.json` |
| `text.py` | нормализация, токенизация, стемминг, стоп-слова, маскирование ПДн |
| `lexicon.py` | группы синонимов, поиск фраз в запросе |
| `spell.py` | опечатки и неверная раскладка клавиатуры |
| `index.py` | BM25 по полям |
| `engine.py` | `SearchEngine.search(q, context, k)` — весь конвейер |
| `ranking.py` | бизнес-сигналы, нейтральные значения при отсутствии, relevance gate |
| `suggest.py` | автодополнение и связанные запросы |
| `store.py` | журнал поисков/событий, аналитика |
| `main.py` | FastAPI: `/health`, `/search`, `/suggest`, `/event`, `/analytics`, демо `/` |

## Принципы
- Релевантность сначала; бизнес-сигналы только внутри полосы хороших кандидатов.
- Отсутствующие поля (маржа, популярность) = нейтральные 0.5, с флагом в ответе. Ничего не генерируется.
- Каждое улучшение — переключатель в `config`, измеряется в `scripts/evaluate.py` (ablation).
- Данные `data/synthetic/*` — собственная синтетика команды, не данные заказчика.
